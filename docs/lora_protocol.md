> 状态：设计稿，待 DX-LR22 手册核实后定稿（见 §11 待核实清单）
> 适用硬件：DX-LR22（433MHz，UART 接口，M0/M1/AUX 引脚，AT 指令配置）
> 关系：取代 `docs/diy-smart-assistant/docs/lora_protocol.md` 中的协议设计部分；
> 该文件中的 DX-LR22 AT 指令表仍为驱动 AT 层的厂商参考，未核实部分以手册为准。
> 设计取舍来源：用户旧项目 UART 串口协议（命令操作符/错误码表沿用，ASCII+JSON
> 与结束符扫描机制因空口带宽与无线包特性弃用，见附录 A）。

## 0. 设计目标与信道预算

目标场景（按优先级）：

1. **文本/短消息互发**（几十字节，秒级送达）
2. **语音留言**（微信式：录好→压缩→后台传输→对方收听）
3. **设备指令与状态同步**（遥控、心跳、在线感知）
4. **小型数据同步**（配置片段、日程条目，几十 KB 级）

明确不做：实时对讲、大文件、图片原图、全双工通话。

信道预算（应用层实际吞吐，含协议开销）：

| 档位 | 典型 SF/BW | 吞吐 | 100KB 文件 | 10s 语音(Codec2 3200≈4KB) |
|---|---|---|---|---|
| 高档（语音/文件用） | SF5~7 / 125k | 1~2 kB/s | 1~2 分钟 | 2~4 秒 |
| 中档 | SF7~8 / 125k | 0.3~0.5 kB/s | 3~5 分钟 | 8~13 秒 |
| 低档（远距文本用） | SF9~12 / 125k | 30~150 B/s | 不适用 | 不适用 |

> 档位与 SF 的确切映射需手册核实（§11）。当前设备树 `spreading_factor: 12`
> 为极限距离文本配置，做语音/文件必须切高档，两档策略见 §9。

## 1. 分层总览

```
应用层        命令分发（cmd 码 + op + errCode 表）、会话/聊天记录 UI
传输服务层    可靠传输（分片+滑窗+累积ACK+续传）│ 语音流（无ACK）│ 信标
链路层        定长二进制帧头 + 载荷，寻址/序号/优先级（本文档主体）
驱动 AT 层    模组参数配置（AT+BAUD/LEVEL/MODE/POWE/CHANNEL...），
              复用旧协议的 ?/=/* 语义；裸数据 UART 收发 + AUX 流控
硬件          DX-LR22（PHY 层 CRC、分包 230B、透明/定点传输由模组完成）
```

命令码匹配在上层应用完成，驱动层只认帧格式——沿用旧协议的分层原则。

## 2. 链路层帧格式

### 2.1 空口帧（ESP→模组→对端，模组透明转发载荷）

所有多字节字段**小端**。整帧 ≤230B（模组 AT+PACKET=3 分包上限）。

```
偏移  长度  字段        说明
0     1    magic      固定 0x4C ('L')
1     1    ver        协议版本，当前 0x01
2     1    type       帧类型，见 §3
3     1    flags      bit0 PRI   优先帧（抢占文件传输，见 §7.3）
                      bit1 NOACK 无需链路确认
                      bit2 MORE  分片后续帧（首片=0，中间/末片=1）
                      bit3~7 保留
4     2    dst        目标地址（0xFFFF = 广播）
6     2    src        源地址
8     2    seq        帧序号，发送方按会话递增（回绕处理见 §6.3）
10    1    len        载荷长度 0~200
11    N    payload    载荷，N = len
```

帧头开销 11B，最大载荷 200B（刻意留余量，不顶满 219）。

**CRC 决策**：空口一跳内不再加协议层 CRC——模组 PHY 已做整包 CRC
（AT+CRC 默认开启），坏包在链路层根本不会上交。将来若做一跳中继，
在 flags 保留位加 CRCEN 标志再启用尾部 CRC-16，v1 不做。

**寻址**：2 字节地址与模组 AT+MAC 一致；网络隔离靠信道（不同 AT+CHANNEL
互不干扰），v1 不设独立 network_id。透明模式下所有帧同信道全收，由
`dst` 过滤：只处理 dst==本机 或 dst==0xFFFF 的帧，其余静默丢弃。
第一版用透明传输（驱动改动最小），帧内自带寻址；后期吞吐吃紧再切
定点传输（AT+MODE=1），帧头格式不变。

### 2.2 ESP↔模组 UART 边界（半包/粘包的真正战场）

旧协议的"扫描缓冲区直到 `;`"要回答的三个问题，在这里的新答案：

1. **帧与帧的间隔**：ESP 侧发送保证每帧一次 write，帧间留出模组分包
   间隔（TX_GAP，默认取 2×当前档位单包空中时间，待手册确认模组是否
   按固定分帧窗口切包）；
2. **连续两帧半包/粘包，状态机怎么恢复**：模组→ESP 方向两包可能背靠背
   到达，UART 流上没有包边界。解析状态机三态：
   `HUNT（扫魔数 0x4C）→ LEN（读到 len）→ PAYLOAD（收满 len 字节后分发）`。
   - 收满即交付，剩余字节留在缓冲区继续 HUNT（天然处理粘包）；
   - 任意状态超时（RX_GAP = 3×单包空中时间）或 magic/len 非法 →
     丢弃当前半包，回 HUNT 重新同步（天然处理半包）；
   - 无"整体 5 秒"式挂起：每帧边界由 len 显式给出，不会无限等结束符。
3. **轮询节奏**：沿用 lora.c 现有 tasker 周期接收（50ms Little 任务），
   每轮把 UART 缓冲区读空交给状态机即可，无需额外超时逻辑。

## 3. 帧类型定义

| type | 名称 | 载荷格式 | ACK | 说明 |
|---|---|---|---|---|
| 0x01 | DATA | 消息子头(§6.1)+数据 | 是 | 文本/文件分片，可靠传输 |
| 0x02 | VOICE | Codec2 帧流 | 否 | 实时语音流，NOACK+PRI |
| 0x03 | CMD | op(1B)+cmd码(2B ASCII)+参数 | 是(CMD_ACK) | 设备指令，见 §5 |
| 0x04 | CMD_ACK | code(1B)+errCode(1B)+结果 | — | 对 CMD 的响应 |
| 0x05 | DATA_ACK | msg_id(2B)+累计seq(2B)+NACK位图(2B) | — | 滑窗确认，见 §6.3 |
| 0x06 | BEACON | name[16]+battery+status+cap | 否 | 在线发现，见 §8 |
| 0x07 | PING | 空/时间戳 | PONG 可选 | 手动链路测试 |
| 0x08 | PONG | 回显载荷 | — | |

## 4. 命令层（沿用旧协议语义，二进制化）

### 4.1 CMD 载荷

```
偏移 长度 字段
0    1    op     0x00 = 赋值(set)   ← 旧协议 '='
                 0x01 = 查询(get)   ← 旧协议 '?'
                 0x02 = 执行(exec)  ← 旧协议 '*'
1    2    cmd    命令码，2 字节大写 ASCII（如 "PN"=Ping）
3    N    param  参数，二进制 TLV 或定长结构（按命令码定义，禁 JSON 上空口）
```

旧协议"需要回应 X# / 静默 X!"的语义映射为：需要回应 → 发 CMD 等
CMD_ACK；静默（如周期状态类）→ 直接用 BEACON 等 NOACK 帧，不占
CMD 通道。

### 4.2 响应与错误码

CMD_ACK 的 `code` 沿用旧协议取值：0=失败 1=成功（旧协议 2=连续包、
3=非主界面为其 UI 特有语义，本项目不用，值保留防混用）。
`errCode` 表沿用旧协议并扩展：

| errCode | 含义 |
|---|---|
| 0 | 未知错误 |
| 1 | 参数错误 |
| 2 | 命令不支持（非法命令码，上层分发时判定） |
| 3 | 设备忙 |
| 4 | 超时 |
| 5 | 存储错误（Flash 写失败/空间不足） |
| 6 | 拒绝（低电量/白名单外） |

CMD 超时无响应 = 重发 2 次（间隔随档位，§9），仍无响应报上层 4（超时）。

### 4.3 初始命令码表（v1 只实现前三个）

| cmd | 名称 | op | 说明 |
|---|---|---|---|
| PN | Ping | * | 链路探测，对端回 CMD_ACK |
| ST | 状态查询 | ? | 回电量/存储余量/信号/版本 |
| NM | 名称设置 | = | 设置对端显示名（持久化 NVS） |
| VM | 语音留言通知 | * | 参数=msg_id+len，通知对端准备接收 |
| TX | 文本消息 | * | 参数=消息子头+UTF-8 文本（单片直发） |

## 5. 可靠传输服务（文本/文件/语音留言共用）

### 5.1 消息子头（DATA 帧载荷前 6 字节）

```
偏移 长度 字段
0    2    msg_id     消息标识（发送方自增，断电唯一性由 NVS 序号保证）
2    2    total      消息总字节数
4    2    offset     本片在消息中的偏移
6    N    data       ≤194B 数据
```

> 旧文档的 48B 负载改为 194B：帧数和 ACK 次数减少约 4 倍。

### 5.2 滑窗 ARQ

- 窗口 W=4（高档位下 4×~30ms 空中时间，等待成本可忽略）；
- 发完一个窗口 → 等 DATA_ACK（超时公式见 §9）→ 收到则按 NACK 位图
  重传缺片，超时未收则整窗重发；
- 整窗重发最多 3 次，仍失败 → 消息标记 MSG_STATUS_FAILED，UI 提示，
  支持手动重发；
- 窗口间随机退避 50~200ms，叠加模组 LBT（AT+LBT 建议开启）防碰撞。

### 5.3 续传与序号

- **断点续传**：接收方把已落盘的最高连续 offset 放进 DATA_ACK 回带；
  重发时发送方从该 offset 续传，不重头开始。
- **seq 回绕**：seq 为 u16；累计确认按"落在窗口内的模 65536 相对位置"
  判定，实现时提供 `seq_in_window()` 辅助函数，不做数值大小直接比较。
- **去重**：接收方按 (src, msg_id, offset) 幂等落盘，重复片静默丢弃。

## 6. 语音服务

### 6.1 编码（替代旧文档 PCM/ADPCM 方案）

- 编解码：**Codec2 3200bps**（8 字节/20ms），预留 1600/700C 作为远距档；
  PCM/ADPCM 因超信道容量 16~60 倍，弃用；
- 采样：I2S 麦克风 16kHz→重采样 8kHz 单声道→编码；
- 播放：解码→8kHz→MAX98357A。

### 6.2 语音留言（v1 主体）与实时流（v2 预留）

- 语音留言：录音完成 → 整段编码落盘 W25Q128 → 走 §5 可靠传输发送 →
  全片 ACK 后标 MSG_STATUS_SENT。10s 语音≈4KB≈高档 2~4s 送达，
  60s 语音约 1 分钟，UI 按"发送中/已发送/失败"呈现；
- 实时语音流（预留）：VOICE 帧 100~200ms 音频/包（40~80B），NOACK，
  丢帧靠序号感知+静音插补；端到端延迟目标 0.5~1s。

### 6.3 信道仲裁

VOICE/PRI 帧活跃期间，可靠传输服务挂起当前窗口（已发片保留状态），
信道静默 500ms 后自动续传——半双工单信道上语音优先。

## 7. 设备发现与在线

- 开机后发 1 次 BEACON，此后每 5 分钟周期发 1 次（NOACK，开销可忽略），
  随机化 ±30s 防同发碰撞；
- 收到 BEACON 更新邻居表（name/battery/last_seen），UI"附近设备"列表；
- 旧文档"Beacon→回复→ACK 三步握手"删除：无连接协议，邻居表即发现，
  发消息失败本身就是离线信号。

## 8. 参数档位与超时

| 档位 | LEVEL(待核实) | 用途 | 单包200B空中时间 | ACK超时 | TX/RX_GAP |
|---|---|---|---|---|---|
| FAST | 高档 | 语音/文件/近距文本 | ~30ms | 110ms | 60ms |
| NORMAL | 中档 | 常规文本 | ~150ms | 350ms | 300ms |
| SLOW | 低档 | 紧急远距短文本 | ~2.8s | 5.7s | 5.6s |

> 表内数值为 SF7/SF8/SF12@125kHz 的 PHY 计算值，LEVEL 映射待手册核实。
> 公式：ACK_TIMEOUT = 2×airtime(len) + 50ms；两档策略：消息按类型选档
>（语音留言固定 FAST，文本默认 NORMAL，用户可强制 SLOW）。

模组基础配置（驱动 AT 层，改后 AT+RESET 生效）：UART 115200（同步设备树
`uart1.baud_rate`，9600 会卡死高档位空口）、AT+PACKET=3(230B)、AT+LBT=1、
AT+POWE 按合规压到当地限值（433MHz 微功率 10mW，量产需换 470~510MHz
版本或降功率）。

## 9. 消息存储（沿用旧文档，微调）

- 目录：`/lora/inbox|outbox|draft`（原 `/loRa_messages/` 命名弃用）；
- 文件名：`<msg_id_hex>.msg`——**不用时间戳命名**（设备时间依赖 SNTP，
  不可信），时间戳放消息头字段，无网时为 0；
- 消息头沿用旧文档 `message_header_t`（magic 'LORA'、version、msg_id、
  sender/receiver、timestamp、type、status、data_length），status 状态机
  UNREAD/READ/SENT/FAILED/DRAFT 不变；
- 接收中消息先写 `<msg_id>.tmp`，全部落盘后原子改名，配合 §5.3 续传。

## 附录 A：旧 UART 协议取舍对照

| 旧协议要素 | 处置 | 理由 |
|---|---|---|
| `=`/`?`/`*` 三操作符 | 沿用（编码为 op 字节） | 语义清晰，覆盖 get/set/exec |
| cmd 码上层分发、驱动不管 | 沿用 | 分层正确 |
| errCode 0~4 错误表 | 沿用并扩展 5/6 | 覆盖存储/策略拒绝 |
| 需要回应/静默两种模式 | 沿用（映射为 CMD 与 NOACK 帧） | |
| 起始符 X# / X!、`;` 结束符 | 弃用 | 无线整包原子到达，结束符扫描多余且怕假同步 |
| 半包扫描 + 50ms/5s 超时 | 改为魔数+长度域三态状态机 + 随档位超时 | 无线包边界由 len 显式给出，不会挂起 |
| ASCII 命令码 1~7 字节 | 定长 2 字节 | 空口按字节计费 |
| JSON 响应体 | 弃用，仅调试串口可用 | `{"code":1}` 壳 12B ≈ SF7 下 10ms 空中时间 |
| 协议层 CRC-16 | v1 弃用（PHY 已有），留中继标志位 | 一跳内冗余 |
| code=2 连续包 / 3 非主界面 | 弃用 | 旧项目 UI 特有语义 |
